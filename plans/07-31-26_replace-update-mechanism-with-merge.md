# career-ops: replace update-system.mjs's checkout mechanism with git merge

## Context

`plans/07-31-26_fix-update-durability-gap.md` set out to stop `update-system.mjs apply` from resurrecting the 16 non-English `modes/{lang}/` directories this fork deliberately removed. That fix (`.update-exclude` + a standalone `prune-update-excludes.mjs` run after every `apply`) was implemented and tested — but testing it against a **real** `apply()` run (in an isolated copy, not the live repo) surfaced a much bigger problem than directory resurrection.

`apply()`'s old design unconditionally `git checkout FETCH_HEAD --`s every path in a fixed `SYSTEM_PATHS` list, with no regard for whether the local copy of that file had been hand-edited. A live test run confirmed this wipes out **any** local customization to **any** `SYSTEM_PATHS` file — not just the deleted directories. Concretely, in the same test run, `apply()` silently reverted this session's `modes/oferta.md` Block F edit back to upstream's full STAR+R table, with zero warning that it had happened. The only reason the language directories stood out as a "bug" is that they're easy to notice missing; a content edit reverting silently is not.

A second isolated test showed the actual fix was already available and, in fact, already precedented in this repo's own git history (a prior `Merged upstream/main with local/main` commit): this repo has a real shared-history relationship with `https://github.com/santifer/career-ops.git` (a configured `upstream` remote, common ancestor found via `git merge-base`). Running `git merge upstream/main` in an isolated copy auto-merged upstream's 199 commits of drift against this fork's 7 local commits cleanly for the vast majority of files — **including a clean auto-merge of `modes/oferta.md` that kept the Block F edit intact**, `modes/interview-prep.md`'s auto-trigger section, and `modes/reply-watch.md`'s Step 3, all correctly combined with whatever upstream changed in those same files. It only stopped for 8 genuine content conflicts (both sides touched the same lines) and modify/delete conflicts on exactly the paths this fork intentionally removed.

## Decision (user-directed)

Replace `update-system.mjs`'s `apply()`/`rollback()` internals with the git-merge-based mechanism, inside `update-system.mjs` itself (not a separate wrapper script). Retire `prune-update-excludes.mjs` — its exclude-parsing/matching logic is folded natively into `update-system.mjs`, since the self-reexec problem that forced it to live outside `update-system.mjs` no longer exists in the merge-based design (see below).

## Why the old self-reexec apparatus can be deleted entirely

The old design's `apply()` unconditionally re-executed itself as a child process after checking out upstream's `update-system.mjs`, purely to solve a bootstrapping problem: an old local updater needs the NEWEST `SYSTEM_PATHS` list (which only the newest code knows) before it can correctly checkout all current system files. That required `resolveReexecCheckout`/`relativeImportSpecifiers` (compute the newest updater's own import closure so the re-exec doesn't crash with `ERR_MODULE_NOT_FOUND`), `CAREER_OPS_UPDATE_REEXEC`/`CAREER_OPS_UPDATE_BACKUP_BRANCH` env vars to carry state across the process boundary, and a dedicated re-exec timeout budget (`reexecTimeoutMs`, `UPDATE_PATH_CHECKOUT_BUDGET_MS`, `REEXEC_BUFFER_TIMEOUT_MS`).

A `git merge` has no such bootstrapping problem: it operates on the full tree diff between two commits, so any file upstream added (including changes to `update-system.mjs` itself) is picked up automatically without needing any manifest to be "known" in advance by the currently-running code. All of the self-reexec machinery is dead weight in the new design and was removed.

## What changed

1. **`update-system.mjs`** — `apply()` and `rollback()` rewritten:
   - `apply()`: lock file → backup branch + WIP stash (unchanged rationale) → `git fetch $CANONICAL_REPO main` → `git merge-base --is-ancestor FETCH_HEAD HEAD` short-circuit if already current → `git merge FETCH_HEAD --no-edit`. On conflict: auto-resolve only `DU` (deleted-by-us) conflicts whose path matches `.update-exclude` via `git rm`; any other conflict stops the process with the file list and manual-resolution instructions, leaving the merge in progress (never guesses, never auto-commits over an unresolved conflict). After a successful merge (clean or auto-resolved), an unconditional sweep removes any `.update-exclude` path still present — this catches upstream adding a brand-new file inside an excluded directory, which would otherwise auto-merge with no conflict at all (nothing local to conflict against). Then a spot-check warns (doesn't abort — the merge is already committed) if the diff touched a tracked path documented as user-layer. Then skill-entrypoint materialization, `npm install`, `playwright install`, dashboard rebuild (all unchanged in spirit, just diffing against the backup branch instead of `HEAD` since `HEAD` now already includes the merge).
   - `rollback()`: `git reset --hard <backup-branch>` in one step (refuses on a dirty working tree first). Replaces the old per-path restore-or-remove loop entirely — a merge only ever produces a small number of commits on top of the backup branch, so resetting undoes all of it at once.
   - Removed: `resolveReexecCheckout`, `relativeImportSpecifiers`, `REEXEC_FALLBACK_FILES`, `mergePathLists`, `reexecTimeoutMs`, `UPDATE_PATH_CHECKOUT_BUDGET_MS`, `REEXEC_BUFFER_TIMEOUT_MS`, `CAREER_OPS_UPDATE_REEXEC`/`CAREER_OPS_UPDATE_BACKUP_BRANCH` env vars, `revertPaths`, `addPaths`, the "self-loading, no static relative imports" constraint and its file-header comment (only existed to support self-reexec).
   - Added: `parseUpdateExclude`/`pathMatchesExclude` (exported, same shape as the retired `prune-update-excludes.mjs`), `loadUpdateExcludeEntries`, `autoResolveExcludedConflicts`, `pruneExcludedPaths`, `CONFLICT_STATUS_CODES`.
   - Kept unchanged: `check()`, `dismiss()`, `SYSTEM_PATHS`/`USER_PATHS`/`BOOTSTRAP_PATHS`/`extractArrayFromSource` (no longer drive checkout, but stay as the documentation/coverage manifest `validate-system-paths-coverage.mjs` and several test-all.mjs checks depend on), skill-entrypoint materialization (`ensureSkillEntrypoints`/`prepareMaterializedSkillEntrypointsForStage`, unrelated to the checkout/merge distinction).
2. **`prune-update-excludes.mjs`** — deleted. Its logic now lives natively in `update-system.mjs`.
3. **`.update-exclude`** — header comment updated to describe the native mechanism instead of the retired standalone script.
4. **`modes/_custom.md`** — House Rules rewritten: no more "run the prune script after apply" step. New guidance: when `apply` reports unresolved conflicts, resolve by hand then `git commit --no-edit`; if `update-system.mjs` itself ever conflicts in a future update (expected, since upstream still ships the old checkout-based updater — see below), resolve in favor of keeping this fork's merge-based version.
5. **`AGENTS.md`** — Update Check section simplified to describe the merge-based flow.
6. **`DATA_CONTRACT.md`** — `prune-update-excludes.mjs` entry removed; `.update-exclude` entry updated to say it's read natively.
7. **`updater-migration-tests.mjs`** — rewritten. Kept the `SYSTEM_PATHS`/`BOOTSTRAP_PATHS`/`USER_PATHS` array-membership and collision checks (still valid — array membership is orthogonal to checkout vs. merge). Replaced the self-reexec-specific pattern checks with checks for the new merge-based invariants (fetch, ancestor short-circuit, merge, DU-conflict auto-resolution, refuse-to-guess-on-other-conflicts, unconditional exclude sweep, stash-before-branch, reset-based rollback, dirty-tree refusal) plus explicit absence checks for the retired self-reexec symbols.
8. **`test-all.mjs`** — removed the two self-reexec-specific tests (`relativeImportSpecifiers` extraction, the standalone-import `#1706` end-to-end regression) and the dead `reexecTimeoutMs`/`UPDATE_PATH_CHECKOUT_BUDGET_MS`/`REEXEC_BUFFER_TIMEOUT_MS` timeout-budget test; replaced with an absence check for leftover self-reexec machinery. Fixed the dashboard-rebuild regex to match the new `baseRef`-parameterized diff call. Replaced the `prune-update-excludes.mjs`-specific invariant test and script registrations with tests for `parseUpdateExclude`/`pathMatchesExclude` and the new merge/exclude-native invariants. Left untouched: the skill-entrypoint materialization tests (12a/12b/12c) — that mechanism (symlink-incapable filesystems) is unrelated to the checkout/merge distinction and still applies verbatim.

## What does NOT change

- `SYSTEM_PATHS`/`USER_PATHS`/`BOOTSTRAP_PATHS` arrays are untouched — they no longer drive `apply()`'s checkout loop, but remain the documentation/coverage manifest for `validate-system-paths-coverage.mjs` and various `test-all.mjs` doc-consistency checks.
- `check()`/`dismiss()` — unrelated to the checkout/merge distinction.
- Skill-entrypoint materialization for symlink-incapable filesystems (Windows) — orthogonal concern, unchanged.
- No new remote is required; `apply()` still fetches by URL (`git fetch $CANONICAL_REPO main`) rather than requiring a named `upstream` remote to be pre-configured, for portability across installs that may not have one set up.

## Known follow-on consequence (accepted)

`update-system.mjs` is still listed in `SYSTEM_PATHS`, so a future real upstream release will very likely produce a genuine merge conflict **on `update-system.mjs` itself** (upstream still ships the old checkout-based updater; both sides touch the same functions). This is expected and desired — git stopping to ask is exactly the improvement over the old design silently overwriting. The `modes/_custom.md` house rule documents the correct resolution: keep this fork's version (`git checkout --ours -- update-system.mjs`), optionally hand-porting any genuinely new unrelated content from upstream's side (e.g. new `SYSTEM_PATHS` entries for files this fork would still want).

## Verification

- `node --check update-system.mjs` / `node --check test-all.mjs` — both pass.
- `node updater-migration-tests.mjs` — 66/66 pass against the rewritten `update-system.mjs`.
- `node test-all.mjs` — full suite, including the new/updated update-system tests.
- Live test in an isolated scratchpad copy (not the real repo): `git fetch upstream` + `git merge upstream/main` against 199 commits of real drift auto-merged cleanly for `modes/oferta.md` (kept Block F), `modes/interview-prep.md` (kept the auto-trigger section), `modes/reply-watch.md` (kept Step 3), and `update-system.mjs` itself, with only 8 genuine content conflicts and the expected modify/delete conflicts on `.update-exclude`-listed paths.
- Follow-up: run the actual rewritten `apply()` (not a raw `git merge`) against a fresh isolated copy to confirm the auto-resolve/prune/conflict-reporting code paths behave as designed before ever running it against the real repo.
